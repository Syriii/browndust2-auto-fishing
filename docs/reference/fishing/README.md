资料按三个层次使用：攻略列出某鱼**可能携带**哪些机制；当前帧提供**实际出现的外观**；控制器根据可信位置和状态决定**是否允许动作**。鱼種机制按两份来源并集准备，不能因资料列了一个技能就预先按键。未知外观保留原图及未确认状态，不反向改写历史鱼种和命中结果。

简体客户端优先。`fish_id` 是稳定身份，不因改名、译名更新或鱼图替换改变。`name_zh` 是简体参考展示名，`name_tw` 和 `aliases` 保留原文、其他译名及有来源的笔误；`client_name_verified=false` 表示尚未核实用户客户端的准确字样。普通繁简转换不等于本地化译名映射，不以模糊相似度自动确认鱼种。

## 后续更新

1. 先读取来源原页的钓鱼正文、六岛昼夜表和配图；记录实际读取日期、页面更新时间、具体章节。GameKee 为动态页面，普通 HTTP 获取的 HTML 壳不能当正文快照。
2. 将原图、结构化摘录、OCR 中间结果和 SHA-256 清单存到 `.local/maintenance/guide-catalogue-YYYYMMDD/`。公开仓库保留事实摘要、来源、必要的回归小图；不整篇转载社区作者文章或将作者个人鱼获记录当用户记录。
3. 对鱼种编号做差异比较。新增鱼种增加新 ID；已有 ID 不因排序变化重编号。机制按来源并集，来源未列出某技能不等于证实没有；删除机制须记录版本变更或反证，不能静默覆盖另一来源。
4. 变更名称时追加经核实的别名，并记录客户端、语言和依据。昼夜、距离、尺寸等事实冲突单独记在 `notes` 与来源表；不能以机制并集规则合并矛盾数值。
5. 更新 JSON 后运行 `python scripts/checks/render_fishing_catalogue.py` 生成图鉴表，再运行 `--check` 及 `tests.unit.test_fishing_catalogue`。新增机制同时更新代码目录、观察线索、动作边界和真实正负例；控制变更还需机制回放，资料更新不自动发布 EXE。

当前原始资料存放于 `.local/maintenance/guide-catalogue-20260914/`：84 张鱼图、23 张机制图、图片 OCR 与结构化事实。以前的巴哈机制原图继续保留在 `.local/maintenance/guide-mechanism-audit-20260909/`。来源图片缺失、网址不可达或哈希变化时标明状态，不能悄悄用另一张图替换。

## EXE 内置浏览

0.3.11 起，主界面左侧“鱼种图鉴”可离线浏览全部鱼图、搜索简繁名称和译名，并按钓场、时段和稀有度筛选。点击鱼图展示只读详情；鱼图不会自动建立目标任务或捕获记录。原始图与 JSON 的来源哈希同时保留，图片中的作者纪录不作为玩家数据。

客户端名称核对：斗鱼、罗汉鱼、蝴蝶鱼和魔鬼鱼已有成功原图与攻略鱼图对照，JSON 附证据路径；其余名称保持参考译名状态。罗汉鱼对应花羅漢，蝴蝶鱼对应蝶魚；旧资料中的鰈魚误录仅保留为历史查询。
