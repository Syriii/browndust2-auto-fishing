## 基础规则对日志的影响

以下为攻略的规则概括；代码状态单独列在后文。

1. 蓝区为普通命中，黄区为弱点命中；攻略给出的伤害倍率分别为 1 和 2。蓝区会逐渐缩小，没有及时命中也会出现 FAIL。因此，没有对应脚本按键的 FAIL 可以是游戏产生的真实反馈，不能直接算到最近一次按键上，也不能仅据此认定特殊机制惩罚。
2. 某些 QTE 使用绿色维持区，需要按住再松开，该次可以没有黄区。同一条鱼的其他 QTE 仍可能有黄区。“未找到黄色”不一定是颜色识别失败。
3. QTE 中鱼的抵抗感叹号属于技能提示，须与等待上钩阶段的感叹号区分。技能可以叠加，隐形指针还明确没有该提示，不能以感叹号作为所有机制记录的必要条件。
4. 单次命中、QTE 结束、整条鱼捕获是不同事件。攻略用距离归零描述捕获；项目目前仍以奖励结算证据确认捕获，不因色条消失或未出现 MISS 就认定成功。

## 特殊技能清单

下表整理自用户提供的文字，并与主楼核对。名称用简体便于检索，括号保留易混淆的原文名称。影响类别是项目分析分类，不是游戏提供的分类。

| 技能 | 攻略描述的效果 | 后续排查重点 |
| --- | --- | --- |
| 锁普通命中区（鎖一般命中區） | 蓝区变灰，约 5 秒内只能命中黄区 | 区域仍可见不代表可命中；蓝区回退须检查状态 |
| 龙卷 | 指针加速 | 速度、截图到按键的延迟 |
| 咬人 | 受影响位置暂不能按，约 5 秒；图示期间未消除蓝/黄区会扣 2 秒 | 保存图示、色条和计时器；不凭扣时反推某次按键失败 |
| 贝壳阻挡 | 遮挡视线，受影响位置不能按 | 可见性与可操作性均受影响 |
| 喷墨汁 | 遮挡视线 | 保留未处理原图，不把掩膜空白当作区域不存在 |
| 隐形指针 | 指针暂时透明，仍可能隐约可见；无技能感叹号 | 低对比度指针与真正无指针的区分 |
| 冰冻 | 需要快速点击 3 次解除 | 按键次数、间隔及解除后的画面证据 |
| 反弹壁 | 指针碰壁反向，碰撞后壁消失；未碰撞也会延时消失 | 指针轨迹与墙体生命周期 |
| 分身指针 | 额外出现 3 个较浅指针，约 5 秒 | 多候选指针及各自轨迹；不能只依赖单帧亮度 |
| 海草泡泡球 | 5 秒倒数内需单次命中；超时增加距离 130 cm，指针继续 | 距离增加不等于该次普通按键未命中；高等级时可暂忽略处理 |
| 消失弱点命中区 | 黄区消失，直到命中一次蓝区 | 无黄区期间的蓝区处理与黄区恢复 |
| 毒海浪 | 紫色障碍约 3 秒；命中一次可消除，攻略称可忽略 | 紫色内容保留为候选线索，未经图像核对不自动贴标签 |
| 麻痹指针 | 指针减速约 2 秒；命中其他区域也不会提前解除 | 速度改变与持续时间，不假定命中后状态清空 |

绿色维持区另列为基础输入模式，未算进上述 13 项技能。多种技能可能同时存在，未来的记录方式应允许多种候选或“未识别”，不强制给每帧指定唯一技能。

核对入口：[`main.py`](../../bd2_fishing/app/fishing_task.py)、[`qte_strategy.py`](../../bd2_fishing/game/fishing/qte.py)、[`qte_feedback.py`](../../bd2_fishing/game/fishing/feedback.py)、[`catch_result.py`](../../bd2_fishing/game/fishing/settlement.py)。

| 当前实现 | 已有行为及限制 |
| --- | --- |
| 亚特兰蒂斯使用 `FrostStraitQTEStrategy` | 黄区优先；无光标不盲按；连续两次有蓝无黄才允许蓝区回退，同一次重合不重复按键。无绿色按住/松开流程，特殊机制覆盖仍不完整 |
| 指针定位 | 选白色像素最多的一列；没有明确识别真指针和 3 个分身的跟踪逻辑 |
| 红色图示与冰冻 | 实测红色牙齿图示曾触发 19 次旧“破冰尝试”，已移除红色即冰冻的盲按规则。当前避开指针附近红色遮挡；真正冰冻的识别、三次输入和解除确认仍需真实正例 |
| 深渊策略 `AbyssMawQTEStrategy` | 有挡板范围与黄/蓝区选择；不等同于已覆盖所有贝壳、反弹壁及技能叠加情况 |
| 反馈观察器 | 观察 CRITICAL/HIT/MISS/FAIL；按键归属不明保留未确认。游戏反馈与按键归属分开统计，没有自动识别上述技能 |
| 失败证据 | 未命中/未确认时限量保存前后原图、掩膜与时序；有对应策略按键时另附控制决策原图及分支依据，与独立观察图明确区分。未实现“出现任意特殊内容就记录” |
| 整条鱼结算 | 奖励证据充分才确认捕获；计时器接近耗尽、剩余距离大于零等条件只能支持疑似逃脱，其他情况保留未确认或中断 |

## 用于后续样本排查

优先检查实际失败包中的绿色维持区、多指针、黄区消失、遮挡及速度变化；先验证画面和反馈时序，再决定是否修改某个策略。不要仅因当前白/黄/蓝掩膜之外有像素就判为特殊技能，文字、装饰和抗锯齿也会产生额外颜色。

攻略的亚特兰蒂斯鱼表将大独角鲸列为 5000 cm，并列出毒海浪和绿色维持区；这可作为既有 5000 cm 失败样本的排查线索。**距离本身不能确认鱼种或该次机制**，必须回看原图。攻略还将鬼蝠魟和艾里斯列为带分身指针的鱼，可用于后续查找同类样本，不能反向给旧日志补写已确认鱼名。

每次核验应关联同一 `round_id`，检查诊断包 `evidence_id`，区分：观察到的反馈、对应按键是否明确、机制是否有图像证据、整条鱼结果。机制原因不能仅凭一条 FAIL 或 unknown 推导；确认支持后再增加真实正例、负例及技能叠加回归。

攻略获取阶段本身仅整理参考。后续决策取证及本次实机原图驱动的按键修复见[问题分类](../development/error-triage.md)，当前能力以本表和开发状态为准；已部署 EXE 未更新。
