## 已有能力与边界

| 范围 | 当前状态 |
| --- | --- |
| 页面与启停 | 默认待机，按钮控制单个任务；重新启动重建所需状态；停止释放输入与截图 |
| 前台与显示器 | 聚焦失败不运行；失焦、锁屏和窗口几何变化停止；支持单屏内负坐标，不支持跨屏拼接 |
| 抛竿与满包 | 位置受阻先恢复重抛；同轮仍失败才停止；自动清包开关生效 |
| 等待上钩 | 夜间黄色 H 上限 35，已有真实正负例；遮挡、小窗口与其他环境仍需按原图定位 |
| QTE 策略 | 保留已有黄/蓝区、挡板和破冰尝试逻辑；没有承诺覆盖全部游戏机制 |
| 反馈与证据 | 默认开启；游戏反馈、按键尝试和归属未确认分开记录；失败包可附控制决策原图 |
| 整条鱼结果 | 奖励证据充分才确认捕获；疑似超时逃脱保留推断属性，中断单独记录 |
| 日志 | 文件保留细节，页面筛选只影响展示副本；轮次与证据 ID 用于关联记录 |

特殊机制逐项覆盖见[机制参考](../reference/fishing-mechanics.md)。绿色维持、多指针及其他机制不能因已经记录到反馈就认定策略已支持。

历史已测试功能与当前正式入口的逐项核对见[已验证功能清单](verified-features.md)。旧实验分支与旧 main 已在 2233919 汇合，后续重构保留了该版本的反馈、结算、停止与采集能力；不需要将旧目录再引入当前仓库。

## 验证与发布边界

历史实测包括本机 875×492 客户区、真实反馈与部分确认捕获样本，也记录过未捕获和未知结果；不能据此推算百分之百命中率。其他分辨率、语言和机制叠加需另行验证。

GitHub 源码、构建产物和用户电脑已有 EXE 分别管理。源码更新不自动覆盖已有 EXE；发布版功能以其构建提交和验收记录为准。

## 暂缓与后续线索

- 低级 QTE 特殊机制补全、非基础内容自动检测仍待后续确定，不作为已确认故障。
- 装扮遮挡、真假指针、绿区与黄区消失等按实际失败原图逐项建立回归，不单凭日志下调阈值。
- 多分辨率、混合 DPI、显示器唤醒后重新启动等需要有条件的实机验证，不主动锁屏或让电脑睡眠。

## 当前：结构规范与低时延边界

- runtime 仅保留通用运行能力；通用图像、OCR 类型/读取、文字处理与识别上下文归 perception；游戏观察区域、反馈字形和 QTE 统计归 game。infrastructure 不再反向导入钓鱼图像模块，结算不再从反馈会话借用识别函数。

## 构建元数据位置修正

setuptools 默认将 egg-info 放在 src 顶层，本机此前也采用此默认。现由最小 setup.py 将元数据与中间文件固定到 build，pyproject 继续作为项目元数据和依赖的唯一来源。原 bd2_fishing.egg-info 已移入本机维护备份，该阶段 src 顶层只保留源码包；本轮进一步移除了 src 层，现以目录说明为准。

可编辑安装、wheel 构建、没有 .local 的全新副本、sdist 及从 sdist 再构建 wheel 均通过检查；默认配置与六张模板完整。新增离线包装回归检查生成位置。日志见 .local/maintenance/metadata-*.log；业务代码和部署未改动。
