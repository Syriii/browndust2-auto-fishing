# 黄条首次经过误拒绝：碎片分组与短时边界

## 原因

0.3.8 会话 c6d29910 的观察帧中，完整黄条被真光标光晕切成多段。
旧 `visible_yellow_span` 先找离光标最近的黄色列；孔内的孤立列会让连续支持校验失败，
随后“最近片段”可能只剩 1–2 列。即使光标在真实黄条中间，重合也被否决。
前几次调整允许孔洞宽度没有解决这个分组错误。

代表第 224 轮：完整黄条 [107,130)，光标 x=120；旧结果却为 [125,126)，
因此 narrow_yellow / overlap=None。回放和所有候选见 `.local/maintenance/runtime-20260914/`。

## 实现

- `mechanics/yellow_geometry.py` 从连续实体段中选择光标两侧支持，跳过孔内孤立残色。
  以条体高度缩放支持量和断口上限；只连接当前光标处的内部孔洞，不跨机制禁区、不外扩端点。
- 两侧实体过弱时，仅允许此前两帧完整、稳定的边界辅助；最多 180ms，当前两侧仍须存在黄色。
  修补结果不续期；缺帧、形状变化、目标变化、颜色消失或遮挡都会使记忆失效。
- 重合校验和中心偏好共用同次分组结果。保留同次入区去重、蓝条回退、挡板限制和原输入时序。
- 每轮最多保存三份光标位于黄色碎片之间却被拒绝的控制帧，间隔至少 250ms；记录实体跨度、
  修补来源、光标、取帧时间与去重状态。只缓存已有控制帧，沿用后台编码和轮转。

## 验证与限制

原 41 帧自动回放候选中，32 帧在单帧内解除误拒绝；另外 1 帧用其真实前序观察帧验证了弱边界接续。
剩余 8 帧没有足够连续证据，不把它们强行变成按键正例。稀疏观察帧无法证明这些时刻正式控制循环
是否已有两帧完整边界；需要后续控制帧记录复核，不将离线结果当成游戏命中率。

50 项专项、567 项完整离线回归、Ruff/216 文件格式/112 模块架构通过。
原 M 系列条外、残色、机制遮挡反例仍通过。巨口策略额外识别出挡板的两帧继续禁止跨板修补。
500 次局部目标判断基准中位 0.1443ms、P95 0.1747ms，不包含截图、OCR、机制识别及游戏响应。
