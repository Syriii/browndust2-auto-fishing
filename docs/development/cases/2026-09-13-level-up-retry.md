# 夜间升级提示滞留与关闭重试

0.3.6 的 `22f3e0a0-073` 轮已经捕获鱼获，关闭奖励后出现 27→28 级升级提示。证据为 `event_1789278392337307000_5d99e7b3.zip`，原始客户区 945×532；独立截图和来源校验值保存在 `tests/fixtures/catch_result/level_up_20260913.json`。

## 已确认原因

- 夜间升级标题分数约 0.887，整块属性区约 0.778；后续夜间帧属性分数降至 0.707。旧逻辑将它归为已关闭过的普通鱼获，因此没有升级关闭权限。
- 约 17.6 分钟后白天帧达到标题 0.983、属性 0.918，程序发送了一次升级关闭点击，但之后的截图仍是升级面板。
- `closed_panel_kinds` 已包含 result 与 level_up，旧规则永久拒绝重复关闭。该轮持续恢复约 64 分钟，最终因失焦保护结束。不能把这一轮归为鱼获失败。

记录只能证明调用过点击与面板未消失，无法证明游戏为何没有响应。此次不把它断言为游戏 bug、鼠标丢包或特定时延问题。

## 0.3.7 修复

1. 标题补充真实夜间字形；属性回退到钓鱼等级、活力、力量三行固定文字分别匹配，三行均须达到原 0.88 阈值。仍要求底部关闭提示，缺少任何关键区域都不确认为升级。
2. 升级点击落点使用当前客户区底部提示位置，发送点击前重新识别同类面板。首次点击后间隔两秒最多补点两次；之后每三十秒重新识别再尝试，不永久耗尽升级恢复权限。
3. 原鱼获面板仍只点一次。升级不改变鱼获统计，不在确认待机前抛竿；停止与窗口保护继续生效。关闭记录最多 16 项，原始与最新代表帧固定键覆盖，避免长期重试无限积累。

三行字形和多尺寸模板在初始化构建，仅结算/页面恢复时使用，没有在 QTE 采样循环新增 OCR、磁盘操作或输入等待。
