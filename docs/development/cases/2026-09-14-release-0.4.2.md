# 0.4.2 启动与加载验收

2026-09-14 至 15。证据目录：`.local/maintenance/startup-performance-20260914/`。

## 修复及范围

ttk 将九宫格中心平铺，旧版 5×5 中心在大面板中触发大量绘制。本版扩大到 128×128，元素宽高设置为 0，保持控件布局。仅将背景改为不透明不足以解决此问题。[Tk 官方说明](https://www.tcl-lang.org/man/tcl8.6/TkCmd/ttk_image.htm)。

桌面不再提前导入 session 和 OpenCV／OCR；第一次实际任务仍在工作线程初始化识别资源。图鉴按可见区域解码图片，页面状态不变时复用控件，鱼卡尺寸和状态相同时复用绘制。Canvas 滚动坐标避免 Windows 屏外子窗口偏移导致漏画；销毁鱼卡时解除滚动事件绑定。补充检查发现列表重建时实际请求高度变化不一定触发 Configure，图鉴与鱼获统一在几何计算完成后显式更新滚动范围；网格／列表单次滚到底均有回归。

## 验证

628 项回归通过（104.681 秒），包含新进程轻量导入与任务转发；Ruff、128 模块架构、设置启停／更新窗口通过。图鉴可见检查覆盖 84 种鱼、末尾图片补齐、回页不重建并保留滚动、筛选、键盘焦点、MAX／MIN 和草稿保留。真实 Tk 八页截图布局通过。1307 项文件、128 个内嵌模块与源码逐模块比对、84 张鱼图、ZIP、真实更新恢复以及正常 EXE 两次启动／退出保留配置和 MAX／MIN 通过。

## 性能测量

源码 cProfile 对照确认绘图瓶颈；该局部基准不包含模块导入和 EXE 加载，不能用作最终启动数字。最终数据使用相同电脑的独立新进程，不清除系统文件缓存；以首屏两行十张鱼图完成绘制为加载终点，同时保存截图，不把空白窗口出现算作完成。

## 保留边界
