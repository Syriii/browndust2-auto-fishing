# 多机制组合处理（源码，未重新打包）

## 本次解决的问题

之前的控制流程虽已有同帧仲裁，但泡泡控制只接受一个目标，绿色等待会阻塞整条 QTE，贝壳没有独立的实体避让。深渊挡板分支还可能将落在挡板内部的光标投影到旁边区域，再判断黄条。

现在的优先级和边界如下：

| 情况 | 行为 |
| --- | --- |
| 绿色按键已经按下，需要保持或松开 | 独占本帧动作；遇到遮挡、丢失、反向或超限先释放，不能同时击球 |
| 已定位绿条，但起按端未确认 | 重叠目标仍等待；空间不相交的泡泡可以单独确认和处理，无法定位绿条范围时不猜测 |
| 多个泡泡 | 最多跟踪 4 个，每个独立连续确认与防重复；每帧最多一次输入；相交多义目标或数量超限不输入 |
| 泡泡被其他机制暂时遮住 | 不用遮挡代替消失确认，不重置已消费的按键状态 |
| 贝壳覆盖蓝条或黄条 | 依据两种真实实体模板定位多个贝壳，排除覆盖范围及边缘；允许处理其他可见目标，不主动点击贝壳 |
| 贝壳、分身、只有蓝条同时出现 | 仍选择最亮可信指针，并在未遮挡的蓝条内部连续确认；暗指针不提供输入许可 |
| 光标位于深渊挡板内部 | 等待实际光标离开，不再把坐标修正到旁边黄条授权输入 |

泡泡身份管理为 `mechanics/bubble_targets.py`，单个球的确认规则仍在 `mechanics/bubbles.py`；组合仲裁为 `mechanics/policy.py`；贝壳识别为 `mechanics/shells.py`，汇入 `mechanics/regions.py`。QTE 执行层仍统一发送原有按键动作。

## 证据与验证

贝壳模板来自 EXE 0.3.5 会话 `9e5212d5-369` 的真实双贝壳画面，原图 `tests/fixtures/qte_control/evening_20260912/shells_over_bubble.png`。两张独立时间帧作保留验证，来源/哈希见同目录 `shell-holdouts.json`。模板只覆盖贝壳条体形状；未将“海草破裂残影”当作贝壳或新泡泡。

验证包括真实图在四种缩放下的两个贝壳、其他机制负例、分身光标选择、蓝条回退、绿色长按互斥、不同位置泡泡分别去重、遮挡和目标顺序变化、挡板内光标拒按，以及组合代表图去重/限量。多个泡泡及部分三机制场景是明确合成的状态/图像回放，不能当作游戏消除成功证据。

535 项完整离线回归通过；随后增加紫色线索快速筛选及三机制组合回放，55 项最终相关专项通过。Ruff、格式检查和 108 模块依赖边界检查通过。质量分析约 83.79/100，是静态结构评价，不是命中率。

贝壳资源在模块加载时读取，尺寸模板缓存有界；逐帧不读文件、不新增截图/OCR或睡眠。300 次 19×244 ROI 局部测量，贝壳检查中位约 0.55–0.61 ms、P95 约 0.84–0.97 ms；与完整回归同时运行时抖动更大。此数据不是实际游戏端到端时延。没有对应颜色线索时跳过模板匹配。

## 持续取证

每轮保留首次贝壳图，并最多保存 8 种不同组合的首次代表帧。组合名包含当时可见的绿/紫/红/泡泡/贝壳/多光标候选，使用已有决策帧，编码和写盘仍在后台。独立场景时间线增加 `shell_occlusion`，按键记录增加 `shell_spans`；多个候选仅是外观线索，不等于已确认发动分身机制。
