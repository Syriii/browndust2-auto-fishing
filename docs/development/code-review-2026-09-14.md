## Key Issues (sorted by severity)

### R1 · P1：手动清包脚本未检查前台，也没有异常后的统一输入释放

- **`main`（L 34–41）**：[clean_backpack_once.py](../../scripts/live/clean_backpack_once.py) 构造 `WindowGuard(GAME_TITLE, region)`，沿用 `require_foreground=False`。倒计时后没有确认用户已切回游戏；窗口仍在原处时，即使别的应用在前台，也能继续按 T 和点击。异常路径只退出相机上下文，没有统一释放输入。
- **验证：** 模拟脚本运行，守卫没有启用前台要求；清包抛异常后 `release_inputs` 调用次数为 0。没有发送真实输入。
- **修复：** 给脚本绑定前台/锁屏守卫和 RunControl，并在 finally 统一释放。补“未切回游戏”“中途失焦”“输入异常”回归。

### R2 · P1：清包连续点击没有页面确认，OCR 漏检会再次执行出售序列

- **`_click_clear_backpack_buttons`（L 40–84）、`clear_backpack`（L 31–37）**：[inventory/actions.py](../../bd2_fishing/game/inventory/actions.py) 仅按延时和配置坐标执行五次点击，没有确认背包打开、一键出售、选择、确认框及退出状态。若某一步未生效，后续步骤仍运行；结束后地点 OCR 返回 None 就跳过开包再跑一遍出售序列。地点文字缺失不能证明还在出售页面。
- **验证：** 点击桩返回失败仍收到五次调用；地点 OCR 固定返回 None 时序列被调用两次，第二次为 `open_backpack=False`。实际误点的落点取决于游戏当时页面，本次不宣称已经发生物品损失。
- **修复：** 增加逐步页面读数与动作后确认；只有确认仍在对应出售阶段才续接。缺图/未知页面交回恢复，不用地点 OCR 单独授权重试。

### R3 · P2：Windows 的 `KEEP` / `Keep` 目录会被自动清理

- **`prune_files`（L 21–25）**：[maintenance.py](../../bd2_fishing/infrastructure/maintenance.py) 用区分大小写的 `name != "keep"` 保护目录。Windows 通常不区分路径大小写，用户创建 `KEEP` 后通过 `screenshots/keep` 同样可访问，但枚举返回的名字会绕过此保护。
- **验证：** 在两个独立临时目录分别建立 `keep/important.png` 和 `KEEP/important.png`，强制触发容量清理。前者保留，后者被删；日常达到年龄或容量阈值时走同一删除路径。
- **修复：** 用 `casefold()` 比较保留目录和保护文件名，补混合大小写、嵌套保留目录及容量/年龄两种回归。修复前使用小写 `keep`。

### R4 · P2：启动时已有 150302 提示无法处理，已建立的 OCR 引擎没有传入

- **`_run_entry_check`（L 83–85）**：[fishing/startup.py](../../bd2_fishing/game/fishing/startup.py) 固定构造 `CatchObserver(None, config, region)`。真实 150302 被识别为可关闭面板后，关闭流程调用 [confirm_exhausted_notice](../../bd2_fishing/game/fishing/notices.py)，因 `observer.engine is None` 必然拒绝。`FishingBot.run` 的首次 `prepare_start` 又在轮次恢复 try 块之外，因此任务结束，不能进入运行中的恢复路径。
- **验证：** 使用真实 `notice_150302_20260913.png` 和真实页面识别，得到 `panel/exhausted_notice`；模拟截图与输入后执行启动流程，稳定抛出“体力提示的完整错误码未确认”，点击为 0。运行中已有引擎的分支不受此缺陷影响。
- **修复：** 将会话 OCR 引擎传到启动观察器，继续保留完整错误码和动作前复核；补从真实提示页开始的端到端模拟。修复前手动关闭该提示再启动。

### R5 · P2：配置能读不能保存，合法 INI 写法导致重复选项

- **`update_config_options`（L 23–37）**：[settings.py](../../bd2_fishing/infrastructure/settings.py) 读取使用 ConfigParser，替换却只识别同样大小写的 `key = value`。`LOCATION = 自动识别` 或 `location: 自动识别` 均可正常读取，但保存 `location` 时会追加第二个同名选项，随后抛出 `DuplicateOptionError`。该问题可影响设置保存和开始任务时保存快照；原文件因原子写入前校验而保留。
- **验证：** 分别使用上述两个最小 `[app]` 配置调用保存，均抛重复选项异常，原字节未变。
- **修复：** 让保留注释的替换器与 ConfigParser 的大小写、分隔符及节头规则一致；补合法语法变体和保留其他配置的回归。

### R6 · P2：启动校验接受小数形式的整数，运行时却按整数文本读取

- **`_validate_value`（L 73–78）**：[app/startup.py](../../bd2_fishing/app/startup.py) 对整数界面字段使用 `getfloat()` 和 `is_integer()`，允许 `longest_keep_time = 25.0`；QTE 初始化通过 `getint()` 读取，直接失败。同类预期窗口尺寸字段也存在读写合同不一致。
- **验证：** 默认配置只把该值改为 `25.0`，`prepare_configuration` 返回 `repaired=False`，随后 `getint` 抛 ValueError。正常界面保存会规范化为整数字符串，因此主要影响手工修改/导入配置。
- **修复：** 校验时使用运行端相同的整数解析，或原子规范化整数字段；补启动校验到策略初始化的贯通测试。

### R7 · P2：损坏的更新结果缓存会阻止整个主界面打开

- **`last_result`（L 78–82）**：[app/updates.py](../../bd2_fishing/app/updates.py) 直接解析 `cache/updates/result.json` 并访问 `message`。该函数在主窗口构造 UpdatePanel 时立即调用，坏 JSON 或缺少字段会使主界面初始化失败，而该文件只负责展示上次更新信息，不是恢复事务依据。
- **验证：** 文件内容为 `{` 时抛 JSONDecodeError，为 `{}` 时抛 KeyError；UI 构造调用没有局部降级。正常结果写入是原子的，但外部损坏或无效内容仍会触发。
- **修复：** 对结果缓存限大小、校验结构，读取失败记录诊断并显示默认文案；保持 pending/journal 恢复事务的严格校验。

### R8 · P2：释放一个输入失败，会跳过其他释放或仍被报告为成功

- **`release_inputs`（L 117–125）**：[windows/input.py](../../bd2_fishing/infrastructure/windows/input.py) 连续释放 space/up/t/鼠标，但不检查底层返回值，也未逐项隔离异常。第一项抛错时后面全部跳过；返回 False 时函数正常返回，TaskController 可以记录“按键已释放”。
- **验证：** 模拟第一个 keyUp 抛 OSError，仅尝试 space，mouseUp 没被调用；所有底层释放返回 False 时函数未报错。证明的是失败路径处理缺失，不代表正常释放已失败。
- **修复：** 始终尝试释放所有持有输入，汇总失败并交给任务错误状态；保留输入锁和 FAILSAFE 恢复，禁止因清理失败进入下一轮。
- **依赖合同：** 已核对当前环境的 PyDirectInput：`keyUp` 返回输入事件是否完整发送，`mouseUp` 正常返回 None。实现时必须分别处理，不能将鼠标的正常 None 返回误判为失败；鼠标发送结果需在适配层另行保证。

## Refactoring Plan

1. 优先修 R1、R2：统一实机工具的会话保护，为出售流程补真实页面正负例及中间失败场景。
2. 修 R3、R8：验证保留目录不受大小写影响，任何释放失败都不跳过其他输入，也不显示成功。
3. 修 R4：启动流程注入现有 OCR，引擎缺失时明确降级，不降低错误码确认标准。
4. 修 R5、R6、R7：统一配置解析规则，把非关键缓存损坏隔离到更新文案，不影响钓鱼入口。
5. 将每项复现转成独立回归，验证失败路径后再运行完整离线测试和隐藏 UI 检查。
6. 从 `qte.py` 的决策取证组装开始拆分，保留 `play_qte` 的输入顺序；先补观测再调整时序。
7. 收敛 `FishingBot.wait_for_bite` 的恢复分支和等待时钟重置，避免复制状态清零代码。
8. 保持 `RunStopped(BaseException)`、共享 OCR 锁、有界诊断与当前依赖边界，不为评分重写这些机制。
9. 后续校正旧实机诊断脚本的五地点参数和全局 monkeypatch，逐步复用当前会话入口；不在本轮顺带实测。
10. 发布前单独验证构建清单、资源、更新助手与真实游戏；574 项离线通过不能代替这些验收。

## Security Concerns

R1、R2 影响输入目标和出售操作，R3 影响用户证据保留，R8 影响异常后的输入状态，应优先处理。修复前不能宣传清包流程已具备完整页面确认或全部实机工具已有失焦停止保护。

源码核查未发现本应用使用 eval/exec、pickle 或 `shell=True` 执行用户数据；更新包已有目录穿越、Windows 别名、链接、体积和逐文件哈希检查，受管清单排除配置与运行数据。此次没有对依赖做在线漏洞扫描；未发现新增直接执行入口不等于完整安全认证。SHA-256 是完整性校验，现有本地 ZIP 导入没有发布者数字签名，仍应使用官方 Release 包。
