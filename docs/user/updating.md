# 便携版使用、更新与数据保留

[文档目录](../README.md) · [使用指南](usage.md) · [配置说明](configuration.md)

从 [最新正式 Release](https://github.com/Syriii/browndust2-auto-fishing/releases/latest) 的 Assets 下载 `BD2_AutoFishing-windows.zip`，解压到独立文件夹后运行主程序。无需安装 Python、安装器或手动配置依赖。本文的更新协议从 v0.2.0 起提供；旧版没有更新入口时，先按“手动更新”中的首次迁移步骤处理。

## 文件目录

```text
BD2_AutoFishing/
├─ BD2_AutoFishing.exe       主程序，默认待机
├─ BD2_Updater.exe           更新助手，由主程序调用；也可双击恢复中断更新
├─ _internal/                Python、Tk、OCR 模型、识别资源等配套文件
├─ manifest.json             版本、平台、文件大小和 SHA-256 清单
├─ config/config.ini         个人配置，首次启动生成
├─ data/                     环境检测与校准报告
├─ logs/                     运行日志
├─ screenshots/              异常及特殊场景证据（通常是含图片的 ZIP）
│  └─ keep/                  手工保留的证据，不自动清理
└─ cache/updates/            下载、解压、事务日志及临时恢复备份
```

运行数据目录按需创建。主 EXE、更新助手、`_internal` 和 `manifest.json` 必须成套保留；更新由程序管理，用户不需要逐项复制。整个文件夹可以移动；删除整个文件夹即可卸载，配置与证据也随之删除。

首次启动生成配置并只读检测环境。没有打开游戏时也能进入界面，稍后在设备设置中检测；基础校准不会伪装成游戏的最佳命中参数。以后启动会补齐缺失配置、检查格式及数值，保留有效值和注释；损坏配置备份为 `config.invalid-*.ini`。旧根目录 `config.ini` 或旧单文件数据目录中的配置会在新配置不存在时自动导入，原文件保留。

## 在线更新

主界面运行记录下方进入 **更新与存储**，点击 **检查更新**，发现正式新版后点击 **下载并更新**。程序从固定的官方 GitHub 仓库下载完整 ZIP 及校验文件，准备完成后确认重启。

默认启动待机时检查更新；可在此窗口关闭。不会自动开始钓鱼，也不会静默重启。任务运行、设备检测或校准期间不能开始更新；下载、校验和清理期间不能启动钓鱼。

检查更新出现网络错误或 GitHub 接口限流（如 HTTP 403）时，可以稍后重试，或按下方步骤从 Release
页面下载 ZIP 并导入。版本查询与附件下载使用不同地址，查询失败不一定影响浏览器下载；无需清空配置或重新安装。

## 手动更新

1. 网络不佳时，点击 **打开 GitHub Release 下载页面**，用浏览器下载完整 ZIP。
2. 回到程序，选择 **从本地 ZIP 更新**，选择下载文件，**无需解压**。
3. 等待校验，确认重启，程序自动替换依赖并保留个人数据。

第一版提供文件选择入口，尚未实现 ZIP 拖放和 OTA 增量包。更新以包内清单识别，文件改名不影响本地导入。同版本可重新安装以修复文件；暂不接受降级。旧版不含更新功能时，首次迁移需将新版完整 ZIP 解压到新文件夹，再将旧 `config.ini` 放在新 EXE 旁，首次启动会导入；旧日志与截图可以归入新目录保留。不要仅替换 EXE，也不要直接覆盖解压完整旧目录。

程序无法启动且提示存在中断更新时，可双击同目录 `BD2_Updater.exe` 尝试恢复；恢复失败请保留 `cache/updates` 中的事务及备份。没有待处理事务时，助手只提示，不更改文件。

## 清理与保留

默认保留 30 天，日志历史容量上限 100 MiB，截图证据容量上限 2048 MiB。任一条件超过时优先清理旧文件，设置可在更新窗口调整。检查发生在发布版启动及每小时的待机时段；任务正在运行时跳过，清理不进入 QTE 检测或按键路径。

原有证据分类的份数/容量轮转继续在后台写入器生效，全局保留策略是额外上限。正在写入的日志不由待机清理删除；主日志已有 5 MiB × 4 份滚动机制。`screenshots/keep/` 中的证据不计入自动清理范围，应自行管理空间。

更新缓存按完整事务保留最多 7 天，并受 4 GiB 总量约束；未完成更新的缓存不清理，以保留恢复能力。配置、校准结果与源码 `.local` 的历史维护证据不参与此自动清理。

SHA-256 用于发现文件损坏和内容不一致；它不替代发布者数字签名。本地更新包应从官方 Release 下载。
