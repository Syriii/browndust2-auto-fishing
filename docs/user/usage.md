# 使用指南

[文档目录](../README.md) · [下载安装](../../README.md#快速开始) · [配置说明](configuration.md)

## 首次运行

1. 完整解压 Windows 发布 ZIP，运行 `BD2_AutoFishing.exe`；程序生成配置并保持待机。
2. 在游戏中手动进入钓鱼场景，站到可抛竿位置。客户区应完整位于一块显示器内。
3. 核对左侧 **当前钓场**、**满包时自动清理** 和 **运行时保持唤醒**。
4. 需要时打开 **设备与时延设置**，检测窗口、校准基础等待或手动调整参数，再保存。
5. 点击左下角 **开始钓鱼**。程序尝试聚焦游戏并初始化截图和 OCR，失败时记录原因并结束启动。

已发布 EXE 仍需手动进入钓鱼场景。未打包源码新增了从码头或选岛页启动的导航：手动钓场作为目标，自动模式使用地图中确认选中的已支持钓场，核对启航按钮后进入。许可证需手动购买；游戏主页到码头仍需手动操作。已经位于钓鱼场景时，钓场选项仍用于策略选择，不会自动重新航行。

## 页面和启停

启动页面识别是尚未打包的源码新增能力，详见[页面识别与启动接续](../design/scene-recognition.md)。
待机时确认后抛竿，可关闭弹窗处理后复核，已有 QTE 则接续当前鱼；未知画面限时观察，未恢复则保存现场并停止。
自动选择钓场仍要求识别地点文字，遮挡时需要手动选择实际钓场。已识别等待咬钩时直接继续等鱼，不重复抛竿；该能力仍待实测，不支持任意页面启动。

左侧是任务选项、本机参数摘要和唯一的开始/停止按钮；右侧默认展示当前状态与运行记录。
**设备与时延设置** 将右侧切换为设置表单，**返回运行记录** 切回日志，左侧任务区保留。

运行记录下方提供 **日志目录**、**异常截图**、**更新与存储** 入口。异常截图打开保存目录，不是额外的证据管理页面。

任务开始后，同一按钮变为 **停止任务**；停止请求发出后显示 **正在停止…**，等待释放按键与资源。
运行中设置锁定，不能启动第二个任务；仅使用页面按钮控制，不监听全局快捷键。关闭窗口也会请求停止。

任务运行时游戏需要保持前台可见。失焦、锁屏、移动、缩放或最小化窗口会停止任务。整理好窗口后手动重新开始，不会自动续跑。不要同时使用另一个钓鱼程序。

## 钓场与恢复

目前代码登记了烟波湖、浅岸、寒霜海峡、深渊巨口和亚特兰蒂斯五个地点，**不是宣称游戏只有五个岛屿**。第六岛及其他入口仍待补充真实资料和验证。

自动识别最多读取三次地点文字，失败后可在左侧手动选择实际所在钓场再开始。手动选择不会核实或改变游戏中的地点，应与当前场景一致。

识别到“当前位置无法抛竿”时，程序会尝试向前移动、点击并重抛；同轮恢复后仍失败则停止。该恢复不受自动清包开关控制。

QTE 结束后还要确认结算。当前源码遇到 QTE 超时或结算观察异常时，会保留现场，先释放 QTE 输入，再等待页面恢复。鱼获奖励和后续升级提示分别确认、分别关闭，确认已回到可抛竿的待机页后继续下一条鱼；原未确认结果仍保留。看见 QTE 消失不等于已经捕获鱼。

升级提示处理是 0.2.1 之后新增的源码修复，尚未打包；本机 0.2.1 仍可能在鱼获后接升级提示时停止。

恢复默认额外观察最多 10 秒，沿用连续未确认最多续钓两轮的限制；页面仍未知、清理失败、配置错误或窗口保护触发时停止。此改动已包含在 0.2.1 本机候选包中，尚未实机验收或正式发布；GitHub 的 v0.2.0 仍在 QTE 超时后停止。

## 背包和电源

**满包时自动清理默认开启，会执行出售。** 复选框打勾表示开启，空框表示关闭；关闭后检测到满包就停止，等待手动整理。按游戏满包提示触发，不按固定鱼数清理。关闭 OCR 会影响满包检测，不建议普通使用时关闭。

**运行时保持唤醒** 默认关闭，开启后只在任务期间请求防止系统自动息屏或睡眠。它不会阻止主动睡眠、合盖或锁屏，退出任务后释放请求。

游戏可以完整位于任意单块显示器，包括负坐标屏幕；不支持跨屏拼接。修改显示器布局、热插拔或从睡眠恢复后，等显示稳定再重新开始。远程桌面断开或拔掉显示器可能影响截图。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到游戏、聚焦失败 | 确认游戏可见且未最小化，用设置中的“检测窗口”查看结果，再开始 |
| 无法识别钓场 | 手动选择实际地点；保留 OCR 日志供后续排查 |
| 蓝区或特殊机制未命中 | 从“异常截图”保留该轮证据；已实现判定不代表所有场景已验证 |
| 日志显示未确认 | 查看前后帧与结算；未确认不等于已证实失败，也不能计为成功 |
| 时延建议看起来很小 | 建议只是基础等待精度；按住时间、截图和游戏响应还会产生时延 |
| 检查更新失败 | 在“更新与存储”打开 Release 页面，下载完整 ZIP 后从本地导入 |
| 下载了 Source code，找不到 EXE | 返回 Release 的 Assets，下载 Windows ZIP |

反馈问题时附程序版本、窗口尺寸、发生时间、相关日志及原始 ZIP，具体方法见[日志与诊断](diagnostics.md)。更新、迁移与清理见[更新说明](updating.md)。
