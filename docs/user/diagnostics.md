# 运行记录与维护取证

[文档目录](../README.md) · [实测工具](../development/tools.md) · [机制参考](../reference/fishing-mechanics.md)

失败、未确认结果和异常现场是正常运行能力，不需要调试模式。“逐帧诊断写入文件”仅控制额外逐帧文本，不控制截图与结算观察。旧配置里的 enabled=false、qte_feedback_enabled=false 和 interval_seconds 不再关闭必要取证；个人配置的其他选项和注释保留。

本文对应 v0.2.0 及当前源码。旧 EXE 不会自动随源码变化，旧记录仍可能位于 debug/ 或 diagnostics/，也可能缺少新版字段。更新与保留规则见[便携更新](updating.md)。

## 遇到问题先做什么

1. 从运行记录下方进入 **异常截图**，按时间查找原始 ZIP；从 **日志目录** 找到同一时间段的日志。
2. 保留关联的反馈包、整轮结算包和场景分段，不只截取其中一张图片。需要长期保留时复制到 `screenshots/keep/`。
3. 记录程序版本、窗口客户区尺寸、时延配置、发生时间，以及当时看见的机制与按键结果。
4. 反馈给维护者时提供原始 ZIP 和对应日志；无截图时也保留错误原因。不要用“未确认”代替“已证实失败”。

下文先说明界面与目录，再解释元数据和取证限制；普通使用不需要手工修改这些字段。

## 界面运行记录

默认按“时间 · 符号 / 中文等级 · 进展”展示，例如 `● 进展  第 3 轮 · 开始钓鱼`、`△ 注意  等待上钩超时，正在恢复。`；错误使用 `! 错误`，颜色仅作辅助。

- **运行信息**：抛竿、等待上钩、游戏反馈、整轮结果、清包、恢复和停止原因。按键反馈未确认与游戏明确未命中分别描述，QTE 结束不表示捕获成功。
- **警告 / 错误**：需要关注的失败或功能降级；优先解释影响和后续处理。
- **详细诊断**：显示原始参数、轮次 ID、OCR 读数、像素阈值、模块名和异常堆栈。此筛选只改变展示，不开启逐帧采样。

正常记录保留最近 1500 条，诊断记录单独保留 500 条，避免逐帧信息挤掉进展。队列有上限、投递不等待；格式化在界面线程完成。过载时提示跳过的界面副本数量，不影响文件处理器接收日志；文件队列本身的限额见下文。

“记录逐帧诊断”仍在设置的折叠项内，决定是否产生额外逐帧日志。失败与异常取证始终启用。维护文件保留 DEBUG 和异常详情，无需事先打开页面的详细筛选。允许空白的 OCR 提示区返回空结果时，组件的对应警告只在详细诊断中展示，原始文件等级不变；其他警告和错误仍正常显示。

## 保存位置

- 仓库运行：.local/logs/ 和 .local/diagnostics/。
- 新便携包：日志在 EXE 旁的 logs/，证据在 EXE 旁的 screenshots/。
- 普通 wheel 安装：用户主目录 BD2_AutoFishing/logs/ 和 diagnostics/。

```text
screenshots/               发布版；源码仍为 .local/diagnostics
├── incidents/              任务异常、恢复前现场和带原因的停止记录
├── hook_timeouts/          上钩超时原图、掩膜和检测参数
├── qte_feedback/           MISS/FAIL、按键归属未确认的前后帧
├── qte_scenes/
│   ├── candidates/         特殊外观候选及整轮时间线，不依赖失败
│   └── routine/            没有触发候选的整轮低频时间线
├── catch_result/
│   ├── failures/           疑似逃脱、结算未确认、异常或中断
│   └── success/            已确认鱼获，独立保留
└── keep/                   手工保留的证据，免于全局自动清理
```

显式源码录制工具另在 `.local/diagnostics/` 生成 `qte_live_时间戳/`，普通 EXE 运行不会自行启动该工具。

每份 ZIP 使用时间和唯一标识命名，内含图片及 metadata.json。按 round_id 关联日志，按 evidence_id 确认具体证据。运行图片不会写进源码、识别模板或测试样本目录；有回归价值的样本经整理后另存入 tests/fixtures/。

需要批量复核时，可通过[只读反馈索引工具](../development/tools.md#常用命令)生成原包清单、
未确认分类和同轮上下文链接。工具不改写历史结果，也不把异常包数量换算为命中率。

整轮 `catch_result` 包会额外缓存本轮首次红、紫、绿候选控制图，文件名为
`mechanism_first_red/purple/green.png`（对应三个独立文件）。即使没有发送按键也保留，
并在 `mechanism_frames` 中记录采集时间、原始区域和裁剪坐标；颜色标签不等于已确认技能。
绿色动作执行时另存起按、释放代表图，释放取证排在实际松键之后。目前起按端仍未确认，
正式识别不会自动发送绿色长按。连续场景前后文继续由 `qte_scenes` 保存。

## 哪些情况记录

新源码的场景包在 `metadata.json` 中增加 `appearance_lifecycle`。同类多个红/紫区域、
泡泡候选分别编号；蓝条无黄条、多光标等全局线索也记录观察区间。连续两帧确认出现，
连续两帧未见记为 `disappeared`；采样断档、窗口几何变化、QTE 不可观察、身份交叠歧义
或观察结束记为 `unknown`。这里的“未见”不证明技能被解除，所有实例 `result` 仍为 unknown。

`attempts_in_observed_interval` 仅列该观察区间内的按键编号，不证明输入针对该外观或导致消失。
每轮最多保存 256 个实例，超限计入 `dropped_instances`；同一 `scene_id` 的分段包保留当时快照。
新确认候选不再受上一候选的 0.5 秒间隔抑制，重复候选及前后截图仍受采样和容量上限约束。
旧 EXE 产生的包没有这些字段，不能据此补造历史状态。

| 情况 | 记录内容 |
| --- | --- |
| 初始化、OCR、截图、策略等任务异常 | 错误消息、调用栈、已有游戏帧及其时间和区域 |
| 上钩超时 | 恢复前游戏画面、峰值和最后感叹号 ROI、掩膜、HSV 范围、阈值 |
| 当前位置无法抛竿 | 位置恢复动作前的游戏画面、地点与恢复次数 |
| 满包 | 清包或停止前的现场及自动清包设置 |
| 换岛确认超时 | 当前游戏画面和错误原因；停止本次任务，不继续抛竿 |
| QTE 未命中或归属未确认 | 按键前后、反馈发生时的 ROI，以及可用的控制决策原图 |
| 整轮 QTE 控制达到时间上限 | 只读核对倒计时/结算现场，记录 `control_timeout`，停止任务；不自动关闭面板、补按或进入下一轮 |
| QTE 特殊外观候选 | 多光标、目标存在但亮光标缺失、蓝黄区异常、红/紫/绿色内容的前后观察帧；无按键或最终成功也保存 |
| 每轮 QTE | 有上限的低频时间线，供回看尚未识别的机制；不是连续录像 |
| 整轮未确认、疑似逃脱 | 结算图、计时器/QTE 缓存帧、OCR 依据、逐次反馈与退出原因 |
| 失焦、锁屏等保护停止 | 只使用停止前缓存，不重新截图或发送输入 |

CRITICAL 为暴击，HIT 为普通命中，MISS/FAIL 为未命中；按键归属未确认保持“未确认”。无对应脚本按键的 FAIL 单独记录，不误归给某次输入。蓝区缩完、遮挡或其他机制可能影响反馈，不能仅凭 FAIL 推断特殊惩罚。

只有奖励、数量、尺寸及结算依据充分时才确认捕获。疑似超时逃脱是视觉推断，不是游戏明确失败提示；用户中断不记作逃脱。新岛屿、新语言和特殊机制仍需真实样本验证，未知机制不会被自动命名或判定为已支持。

整轮包的 feedback_diagnostics 记录按键观察队列丢失数 dropped_press_records、归属是否不完整 attribution_incomplete，以及关闭等待后观察线程是否仍在结束 reader_still_running。过载不阻塞真实按键；发生缺失后，本会话后续按键归属保持未知。关闭时封存记录，迟到的识别不会改写已经汇总的账本。证据写入失败会清理本次临时文件，保留此前完整 ZIP。

## 原图与时间对应

反馈未确认包的 `outcome.diagnostics` 记录原 0.75 秒窗口内的有效帧数、未匹配帧数、
旧反馈帧数、最大采样间隔和最高匹配分数。`category` 对应以下观测情况：

| 类别 | 含义 |
| --- | --- |
| no_observation / observation_gap | 窗口内无有效观察，或间隔超过 0.20 秒；说明证据不足，不证明游戏丢键 |
| feedback_not_detected | 有连续观察但未识别到反馈字样，不能区分未显示与漏识别 |
| feedback_not_renewed | 观察到旧字样，未确认新的反馈 |
| superseded_by_input / ambiguous_feedback | 下一次输入到来前未确认，或看到反馈但候选输入不唯一 |
| observer_failed / input_records_dropped | 观察线程异常，或按键观察队列丢失记录 |
| qte_ended | 本轮结束前尚未确认 |

整轮包的 `feedback_diagnostics.unknown_categories` 汇总上述分类，`observer_error` 记录观察线程异常类型。
这些数据来自实际观察过程，旧包不具备这些字段；不能从旧包筛选后的八帧伪造实时采集统计。
整轮超时的 `control_timeout` 保存只读检查状态、原图采集时间/区域、上限及检查错误（若有）；
`timeout_control.png` 为该次 DXcam 原始控制区，结算检查若执行，另存不同来源/时刻的 `settlement.png`。
任务会停止并释放输入，即使看到了结算面板也不自动关闭；请确认页面后再开始。

正常 QTE 结束后的结算检查在完整 `fish_end_wait_time` 预算内复查面板或待机控件，设置范围 0–30 秒、最多检查 151 次，
每次检查响应停止和窗口保护；OCR 耗时另计。首次即就绪时不增加轮询等待，等待时间计入原结算等待。
面板与待机页均未确认时停止；已确认待机页可按续钓次数上限继续，unknown 不改写。
动作前、关闭后和下一次抛竿前复核页面，`resume_first.png`、`resume_latest.png`、`resume_check`
及 `resume_confirmed` 记录相应证据；旧版本包不具备这些字段。
`settlement_first.png` 与 `settlement.png` 分别保留首个有效帧和最终有效帧，
时间见 `first_settlement_at_monotonic`、`captured_at_monotonic`；`settlement_wait_samples` 记录各次是否有图及面板就绪状态。
中断时仅保存已有缓存，无有效图则明确报错；不能用过渡动画推断已经捕获。

上钩包的 peak_hook.png 与 peak_mask.png 是同帧原图及掩膜，last_hook.png 是该等待周期最后有效 ROI；timeout_game.png 复用异常分支在恢复前取得的客户区，与峰值图时间不同，不再重复截图。元数据包含有效帧数、无新帧次数、阈值、坐标、峰值时间和现场来源；context_source 区分复用与独立采集，复用路径的处理耗时不代表一次新的截图耗时。

QTE 失败包最多保留 8 张按键前后及反馈帧。decision.png 若存在，是实际控制决策使用的 ROI；frame_* 是独立观察线程的帧，两者不能混作同一时刻。各掩膜均从各自原图生成，并记录区域及时间。

incidents 复用最近有效帧，每个来源最多每 100ms 更新一次，最多缓存 4 个来源。元数据列出来源、屏幕区域、采集时间、帧龄和帧所属轮次。初始化画面可能明显早于错误，不得将它当作故障瞬间截图。初始化前尚无有效图、截图后端不可用等情况只保存原因，标记 screenshots_available=false，不截取其他桌面内容冒充游戏现场。

## 保存上限和时延

场景取证复用独立 GDI 观察器已有的局部 QTE 区域，不额外采集全游戏画面。
连续两帧候选才触发，超过 0.3 秒的采样断档重置确认；缓存之前四帧及之后约 0.4 秒，
持续候选最多每三秒再次触发；新确认的候选不受上一候选 0.5 秒间隔抑制。低频时间线间隔为
`max(0.5, longest_keep_time / 32)` 秒。颜色标签只是外观线索，不自动认作具体技能或派发输入。
每段最多缓存 80 帧、12 MiB 选中图像，另有四帧预缓存，单帧上限 6 MiB；
段满时非阻塞提交已有图像到后台，再继续保留下一个片段。每轮最多 64 段，共用原有 8 项写入队列。
队列过载或达到分段上限时退回有界优先级淘汰，仍可能缺帧；不在输入路径等待编码或磁盘。
`scene_id` 关联整组，`part` 从 0 编号，`final_part` 标记末段，末段附完整反馈账本。
候选 `event_id`、`context_start/context_end` 用于跨段查找前后文；`evidence_location` 指向事件原图所在段和文件。
分段包仍按文件数量/容量轮转，长期保留的案例需成组复制至维护目录；队列接受也不代表磁盘必定成功。
候选事件最多 64 条、按键元数据最多最近 128 条。元数据记录采样断档及帧/事件丢弃数。
缓存保留优先级为结束帧、每类首次候选帧、其他候选前后帧、普通时间线；
低优先级新帧不能挤掉高优先级旧帧，同优先级淘汰较早帧。仍受总容量约束，不保证每个事件都有连续录像。
`dropped_frame_reasons` 区分超大帧、拒收与各类帧淘汰；候选的 `evidence_file` 指向事件时刻原图，
若为 null，表示该时刻图片不在本段；先查 `evidence_location`，不要直接当作原图丢失。
相距不超过窄光标宽度的相邻亮线不再单独触发多光标候选，原始候选位置及亮度仍保留。
帧内 `pointer_motion` 记录可信位置之间的位移、速度和反向；光标不明确、页面不活跃、
尺寸变化或间隔超过 0.20 秒时断开跟踪，不外推不可见光标、不据此派发按键。
场景包默认候选保留 100 份、普通保留 10 份，分别由 `scene_max_events` 和
`scene_routine_max_events` 控制，目录各自另有约 512 MiB 上限，均不受调试开关控制。
整轮 `feedback_diagnostics` 中的 `scene_observation_error` 表示场景分析异常，
`scene_evidence_submitted` 仅表示是否进入后台队列，不保证磁盘写入成功。

各类失败目录分别默认保留最近 100 份，由 [diagnostics] failure_max_events 控制；成功结算默认保留 10 份，由 max_events 控制。每类自动取证目录另设约 512 MiB 上限，至少保留最新一份。按时间清理最旧 ZIP，跨程序重启继续生效；旧版诊断文件原样保留，不自动搬迁。手动录制目录由录制工具管理，不属于这些自动轮转目录。

便携版另外执行全局待机清理：默认 30 天、日志 100 MiB、截图 2048 MiB，在启动及每小时待机时检查。
逐类轮转保留的最新包仍可能因全局年龄/容量上限被清理；需要永久保留的案例应复制到 `screenshots/keep/`。
配置与校准数据不参与清理，源码 `.local/` 不执行这项全局便携版维护。设置与缓存规则见[更新说明](updating.md#清理与保留)。

PNG 编码、ZIP 写入和旧包清理在后台执行。一般错误与结算共用 8 项有界队列，QTE 失败写入器另有 8 项队列；上钩专用写入器忙时跳过详细包。满队列或写入失败会输出日志。新事件不在输入线程等待磁盘，也不排队发送游戏输入。

初始化和异常恢复分支会额外读取游戏画面；正常逐帧路径只复用已有帧。停止后不补截屏，退出时有限等待后台保存。磁盘不可写、队列持续过载、进程被强制结束或原生崩溃时，无法保证每次都有完整截图。出现问题后及时复制相关 ZIP 和日志，避免长期运行后的轮转淘汰。离线检查不等于游戏端到端时延验收。

## 日志与实测工具

整轮 `feedback_diagnostics.observation_performance` 记录总有效观察数、识别路径计数、
完全相同帧缓存命中数，以及最近最多 128 个有效观察的截图/匹配 p50、p95、最大耗时。
`critical_edges` 表示使用强光暴击备用路径；`white_text` 为原白字路径，另有未识别和类别歧义。
只缓存上一张逐像素相同的文字 ROI（最多 6 MiB），新画面重新匹配；复用结果不复用采集时间，
也不把持续显示的旧字样认作新反馈。上述耗时属于独立观察线程，不包含控制输入和游戏响应。

auto_fishing.log 保留项目 DEBUG 及以上和 RapidOCR 原始警告。主日志每份 5 MiB，保留 3 份备份；auto_fishing.fault.log 追加原生崩溃记录。文件日志由后台有界队列写入，队列上限 4096，为 INFO 及以上预留 256 个位置，过载时报告丢弃数。页面筛选不删除文件日志。

QTE 汇总记录采样、挡板变化与输入次数；逐帧额外文本由 qte_detail_log=true 开启。每轮从抛竿分配轮次 ID，恢复重抛沿用原轮次；“已发送按键”不等于机制已解除或成功捕获。

scripts/live/record_qte_session.py --seconds 45 --feedback --no-full-frames 会实际控制游戏，用于显式授权的限时采样。--probe-outcomes 会刻意尝试不同输入区域，--probe-escape 会不发送 QTE 按键以采集逃脱样本，均不是正常运行模式。完整选项与影响范围见[工具说明](../development/tools.md)。
