## 先纠正冰冻处理结论

冰冻需要专门处理，原先红色触发破冰的意图是应对这一机制。
后续实测只证实红色牙齿图示也会触发旧规则，不能由此推导冰冻机制不存在。
`fb8457b` 移除了红色触发的无条件按键，但没有提供真正冰冻的替代识别与处理，
因此该项属于**误触发防护完成、冰冻处理仍有缺口**，不能说特殊规则已经解决。
同样，红色局部避让只是临时防护，不能代替咬人、冰冻等不同机制的判别。

真正冰冻的方案：确认冰冻状态后进入独立处理阶段，按已确认规则最多执行一组破冰输入；
逐次响应停止并释放输入，检查解除画面后返回普通 QTE；无法确认则留图、明确记为未解除。
“三次点击”来自已有机制资料，输入间隔和解除特征仍需真实序列确认，不能把同一红色区域无限连按。
U01、U50 是最初 60 包中的旧破冰尝试，是否真是冰冻需要看图确认。

## 每类规则有自己的识别、动作和退出条件

| 规则 | 应有处理 | 需要确认的画面或时序 |
|---|---|---|
| 冰冻 | 独立破冰输入，确认解除再恢复普通控制 | 冻结前、冻结中、每次点击后及解除的真实正例；牙齿等红色图示负例 |
| 咬人 | 标出实际受影响区，只在允许区域输入，跟踪图示消退 | 牙齿位置、作用范围、倒计时变化；不能只靠红像素判别 |
| 锁普通命中区 | 灰区排除普通命中，保持黄色命中 | 蓝变灰、黄色保留及恢复阶段 |
| 消失弱点命中区 | U07 已由用户确认：只有蓝条时命中蓝区，再观察黄区恢复 | 其他样本需排除过渡动画、绿色模式或遮挡；蓝区输入后的实际效果 |
| 绿色维持区 | 有状态的按住/松开控制，退出和停止时释放 | 进入绿色模式、边界和结束条件；不能用普通单击代替 |
| 隐形指针 | 跟踪已有轨迹与低对比候选；位置不确定时不猜测输入 | 明暗转换、连续位置和恢复，评估预测误差 |
| 分身指针 | F05/F06 已由用户确认：光标候选中最亮者为真，暗者为分身 | 比较的是光标候选的亮度，不是全图最亮像素；补齐不同亮度、交叠及运动中的回归 |
| 龙卷 | 用连续帧估计速度，缩短决策滞后；保留输入完成约束 | 加速前后轨迹、截图到输入的时间，不直接删除所有等待 |
| 麻痹指针 | 更新运动估计，适应减速及恢复 | 速度变化与持续过程，不沿用加速预测 |
| 反弹壁 | 跟踪墙与指针方向变化，更新有效轨迹 | 碰撞前后、墙消失，区别普通端点反向 |
| 贝壳阻挡 | 局部遮挡与不可操作区域同时处理 | 遮挡形状、真实作用边界、解除画面 |
| 喷墨汁 | 可见性降低时降低定位可信度，保留遮挡前后帧 | 墨迹覆盖、持续与消退，不把空掩膜直接当作无目标 |
| 海草泡泡球 | 独立期限与命中任务，确认完成或距离惩罚 | 倒数、命中反馈、距离变化，区别普通 FAIL |
| 毒海浪 | 独立记录障碍与命中后变化，不强求出现 HIT 字样才算有变化 | 紫色图示前后、是否消除、距离和计时；机制效果与普通反馈分开 |

技能可以叠加，识别结果应允许多个候选。控制层先判断当前输入模式和输入是否合法，
再选择适用机制动作；不能由一个颜色标签直接派发互相冲突的按键。

## 已接入的特殊场景取证

取证与控制分开。颜色、图示、指针或色区异常只生成“待确认线索”，不直接触发机制输入。

1. 已有识别线索出现时，保存前后连续观察帧及当时的按键依据，即使没有 MISS、没有按键、最终成功捕获也保存。
2. 已实现候选包括多条指针、目标存在但亮指针缺失、蓝黄区异常、绿色/红色/紫色内容。技能图示分类、遮挡范围与运动变化识别尚未实现；低频时间线补充留样。颜色不等于某个具体技能。
3. 每轮另外保留有上限的低频时间线，用于回看尚无识别器的新机制；这只能减少漏样，不能保证捕获任意短暂事件。
4. 元数据保留轮次、采集时间、ROI、采集器、候选依据、输入与观察结果；原图、掩膜、决策帧区分来源和时间。
5. 复用已有观察帧，在后台识别和编码写盘；事件去重并限制频率、帧数、内存、队列和磁盘容量，记录丢弃原因。停止后不新截图、不新输入。
6. 特殊候选、普通时间线、失败证据分开轮转，避免大量普通样本挤掉特殊场景。

`scene_evidence.py` 管理有界缓存并提交通用后台写入器，正式 `FeedbackSession` 已接入。
