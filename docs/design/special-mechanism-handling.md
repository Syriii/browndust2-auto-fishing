### 绿色：按画面状态保持与释放

1. 在 QTE 条内部确认绿色区域与深色起始端，结合连续有效帧确认进入绿色模式。
   蓝绿混合时保留完整区域关系；绿色识别不确定时不能直接套“无黄则点蓝”的普通回退。
2. 等待真实指针进入深色起始端，发送一次 keyDown；本次动作由绿色控制器独占，禁止普通策略再发单击。
3. 保持按键期间继续逐帧定位，指针越过起始端后，在绿色有效内部留出边界余量并 keyUp。
   释放条件由当前位置、移动方向和采样间隔决定，不沿用固定 100ms 按住、200ms 暂停。
4. 指针丢失、画面断档、绿色消失、到达最大保持时限或任务停止时释放按键，结束本次尝试并取证。
   恢复普通模式前重新确认画面，不能从一次释放直接推断成功。
5. 从按下到释放作为一个动作事务，记录两个原生输入时刻；普通反馈归属以释放后的观察为主。
   普通点击的现有 750ms 归属规则不随之扩大；长按另有有界的动作期与反馈期。

验收：真实绿区与背景、倒计时圆环、蓝光负例定位；双方向、窄区、蓝绿混合、紫色叠加；
停止/失焦/丢帧必须释放、持有期间无普通按键、不可重复 keyDown。
正确长按造成何种游戏反馈和进度变化仍需专门实机序列验证。

### 紫色：先分离障碍与有效命中区

先识别完整紫色图示及其占据区间，而非对整幅图计紫色像素；生成独立障碍标签，
不让黄/蓝掩膜膨胀后的范围跨过障碍重新变成可点击区。

第一阶段方案是局部避让：优先选择障碍之外的有效黄区；黄色被挡时，只有确认蓝区仍可用且不被其他机制锁定，
才允许选择安全蓝区。没有可靠可用区时短暂等待并重读，保留整轮原有超时，不无限等待，也不为消除紫色连续补按。
该策略可能牺牲输出速度，属于待验证的初始策略，不是已证实最优解。

命中紫色一次消除与点击扣时的攻略说法有差异；主动消除紫色留作单独对照策略，不能默认启用。
验证记录每次图示出现/移动/消失、指针相对位置、蓝黄区是否重合、输入和倒计时变化，
先区分“点击障碍本身”“点击与障碍重叠的目标”“未输入也扣时”。

### 被咬住：追踪牙齿区间与图示倒数

识别牙齿形状和边界，持续更新受影响范围；与普通感叹号、红色倒计时、冰冻分开。
现有局部红色避让只是基础防护，后续用形状与时序限制误判。

第一阶段保留局部避让，继续在未被牙齿覆盖的有效目标区输入，不把整条 QTE 都暂停 5 秒。
如果目标完全被覆盖，只能有界等待或记录无可用区；不得恢复旧“检测到红色就连按破冰”的分支。
图示内倒数交给观察线程读取，不能把它当作整轮剩余时间。

牙齿消失需跨帧确认；普通 HIT/CRITICAL 不清空牙齿状态。
“对牙齿输入能否解除”需要与自然消失及其他目标命中对照；在单次输入前后都保留图示倒数，
没有因果证据时只记消失事实。后续若规则证实可主动解除，再增加独立动作，而非无条件补按。

### 结构、时延与验证顺序

实现按三个职责组织：`perception` 提供通用图像运算；`game/fishing` 内的机制观察、状态与策略决定游戏动作；
现有 Windows 输入适配器执行输入，`runtime` 的取消与释放保护保持通用。
`SceneSignals` 当前只是观察线索，不能未经回归就把候选颜色直接升级成动作条件。

每帧允许多个机制标签；绿色是输入模式，紫色/牙齿是可叠加障碍。
输入仲裁顺序为取消释放、处理已持有的绿色动作、选择当前模式下的有效目标、最多发一个动作。
切换模式时清空旧普通触发状态；暂停或遮挡不能被误当作已经离开目标而重新放行。

控制路径复用现有小 ROI，不增加第二路控制截图，不做 OCR、PNG 编码、同步日志或网络请求。
模式识别在等待进入时确认；已持有按键时，释放不能等待后台 OCR 或取证线程。
边界余量考虑帧龄、可信速度、输入时延估计与定位误差，速度估计失效时不外推跨区输入。
当前基础等待校准不包含游戏端响应，不能冒充这些时延已被自动校准。

实施顺序：先做三类定位及叠加负例回放，再接绿色状态机与统一动作仲裁，再验证紫色/牙齿局部避让，
最后根据单次行为对照决定主动消除规则。离线回放只验识别、动作序列与停止保护；
正式接入后分别验证游戏效果、每帧新增耗时和停止释放，不把一轮捕获当作所有机制验收。

## 先纠正冰冻处理结论

冰冻需要专门处理，原先红色触发破冰的意图是应对这一机制。
后续实测只证实红色牙齿图示也会触发旧规则，不能由此推导冰冻机制不存在。
`fb8457b` 移除了红色触发的无条件按键，但没有提供真正冰冻的替代识别与处理，
因此该项属于**误触发防护完成、冰冻处理仍有缺口**，不能说特殊规则已经解决。
同样，红色局部避让只是临时防护，不能代替咬人、冰冻等不同机制的判别。

真正冰冻的方案：确认冰冻状态后进入独立处理阶段，按已确认规则最多执行一组破冰输入；
逐次响应停止并释放输入，检查解除画面后返回普通 QTE；无法确认则留图、明确记为未解除。
“三次点击”来自已有机制资料，输入间隔和解除特征仍需真实序列确认，不能把同一红色区域无限连按。
U01、U50 是最初 60 包中的旧破冰尝试，是否真是冰冻需要看图确认。

## 每类规则有自己的识别、动作和退出条件

| 规则 | 应有处理 | 需要确认的画面或时序 |
|---|---|---|
| 冰冻 | 独立破冰输入，确认解除再恢复普通控制 | 冻结前、冻结中、每次点击后及解除的真实正例；牙齿等红色图示负例 |
| 咬人 | 标出实际受影响区，只在允许区域输入，跟踪图示消退 | 牙齿位置、作用范围、倒计时变化；不能只靠红像素判别 |
| 锁普通命中区 | 灰区排除普通命中，保持黄色命中 | 蓝变灰、黄色保留及恢复阶段 |
| 消失弱点命中区 | U07 已由用户确认：只有蓝条时命中蓝区，再观察黄区恢复 | 其他样本需排除过渡动画、绿色模式或遮挡；蓝区输入后的实际效果 |
| 绿色维持区 | 有状态的按住/松开控制，退出和停止时释放 | 进入绿色模式、边界和结束条件；不能用普通单击代替 |
| 隐形指针 | 跟踪已有轨迹与低对比候选；位置不确定时不猜测输入 | 明暗转换、连续位置和恢复，评估预测误差 |
| 分身指针 | F05/F06 已由用户确认：光标候选中最亮者为真，暗者为分身 | 比较的是光标候选的亮度，不是全图最亮像素；补齐不同亮度、交叠及运动中的回归 |
| 龙卷 | 用连续帧估计速度，缩短决策滞后；保留输入完成约束 | 加速前后轨迹、截图到输入的时间，不直接删除所有等待 |
| 麻痹指针 | 更新运动估计，适应减速及恢复 | 速度变化与持续过程，不沿用加速预测 |
| 反弹壁 | 跟踪墙与指针方向变化，更新有效轨迹 | 碰撞前后、墙消失，区别普通端点反向 |
| 贝壳阻挡 | 局部遮挡与不可操作区域同时处理 | 遮挡形状、真实作用边界、解除画面 |
| 喷墨汁 | 可见性降低时降低定位可信度，保留遮挡前后帧 | 墨迹覆盖、持续与消退，不把空掩膜直接当作无目标 |
| 海草泡泡球 | 独立期限与命中任务，确认完成或距离惩罚 | 倒数、命中反馈、距离变化，区别普通 FAIL |
| 毒海浪 | 独立记录障碍与命中后变化，不强求出现 HIT 字样才算有变化 | 紫色图示前后、是否消除、距离和计时；机制效果与普通反馈分开 |

技能可以叠加，识别结果应允许多个候选。控制层先判断当前输入模式和输入是否合法，
再选择适用机制动作；不能由一个颜色标签直接派发互相冲突的按键。

## 已接入的特殊场景取证

取证与控制分开。颜色、图示、指针或色区异常只生成“待确认线索”，不直接触发机制输入。

1. 已有识别线索出现时，保存前后连续观察帧及当时的按键依据，即使没有 MISS、没有按键、最终成功捕获也保存。
2. 已实现候选包括多条指针、目标存在但亮指针缺失、蓝黄区异常、绿色/红色/紫色内容。技能图示分类、遮挡范围与运动变化识别尚未实现；低频时间线补充留样。颜色不等于某个具体技能。
3. 每轮另外保留有上限的低频时间线，用于回看尚无识别器的新机制；这只能减少漏样，不能保证捕获任意短暂事件。
4. 元数据保留轮次、采集时间、ROI、采集器、候选依据、输入与观察结果；原图、掩膜、决策帧区分来源和时间。
5. 复用已有观察帧，在后台识别和编码写盘；事件去重并限制频率、帧数、内存、队列和磁盘容量，记录丢弃原因。停止后不新截图、不新输入。
6. 特殊候选、普通时间线、失败证据分开轮转，避免大量普通样本挤掉特殊场景。
