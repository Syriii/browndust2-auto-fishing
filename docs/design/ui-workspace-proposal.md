# 主界面改版草案

2026-09-14，第四版。用户已认可并授权推进实现，已接入 0.4.0 源码，构建交付进度见[当前状态](../development/status.md)。

## 问题与方向

原主界面围绕单次钓鱼设计，日志占据主要空间，图鉴另开窗口。继续加入目标和鱼获记录，会让相关操作散落在多个入口。

建议改成一个主窗口：左侧导航切换钓鱼、图鉴、目标、鱼获，设置位于导航底部。中间页面使用剩余空间，底部任务栏统一显示当前任务、状态和开始／停止。图鉴连续滚动，取消分页。按用户 2026-09-15 的后续要求，钓鱼页运行日志改为默认常驻，任务设置与本次进度并排，为日志保留高度。

## 页面职责

| 页面 | 内容与操作 |
| --- | --- |
| 钓鱼 | 本次任务设置、钓场、目标摘要和运行日志；鱼获在独立页面查看 |
| 图鉴 | 图片、简繁别名搜索、钓场／昼夜／稀有度筛选、机制详情；切换选择模式后多选加入目标 |
| 目标 | 待完成的鱼种、任意尺寸／最大／最小条件、移除和开始使用 |
| 鱼获 | 首次、彩色、最大、最小分别筛选，每条带图，允许查看完整历史 |
| 设置 | 设备、时延和运行参数；避免与本次任务设置重复 |

常用流程为选择目标要求、选择鱼图、保存目标、开始任务、查看鱼获。普通自由钓鱼仍可直接启动，无需先进入图鉴。浏览详情不改变任务；将目标清单用于任务需明确点击。

## 当前交互约定

- 图鉴分浏览和选择目标两种模式。浏览模式点击鱼图只查看详情，没有独立勾选框；选择模式点击整张鱼卡选中，再次点击取消，已选标记本身不设第二个点击动作。
- 2026-09-15 用户确认调整：左侧为密集小图网格或列表，右侧固定详情。图鉴与鱼获共用这一布局；切换视图、筛选或记录时不移动详情区。鱼获按记录 ID 选择，同鱼多次捕获也分别展示对应时间、尺寸和等级。
- 机制字段仅展示明确的具体内容。没有可展示的机制时隐藏该字段，不显示“详情以攻略为准”“暂无资料”等占位文字，也不因此断言该鱼没有特殊机制。
- 列表与网格共用右侧完整资料字段：稀有度、钓场、时段和已知的具体机制。不再显示“别名”字段；繁简名称及其他译名映射保留在搜索数据中，不把语言差异当作详情内容。
- 列表摘要与网格鱼卡的信息保持一致：鱼图、鱼名、时段和彩色标识；列表额外提供展开箭头，去掉右侧独立的“钓场 · 稀有度”，不再维护两套摘要字段。
- 小图在宽窗口每行五张，打开侧栏后仍保持较小图片；表格和列表合并，只保留小图和带缩略图的列表。切换视图、搜索不能丢失已选目标及其条件。
- 图鉴与鱼获的视图切换统一使用网格、列表两个图标，保留选中状态、悬停提示和辅助阅读标签，不再显示“小图／列表”文字按钮。
- 窗口大小不随内容、筛选结果或视图切换变化，内容在窗口内滚动。导航和底部启停栏始终可见；正式程序仍允许用户自行调整窗口大小。图鉴提供钓场、昼夜、稀有度和繁简名字筛选，全天鱼同时属于白天和夜晚结果。
- 目标页直接打开选鱼区，不跳到图鉴再跳回来。图鉴也可以原地选鱼，点击“保存并使用”后直接用于本次钓鱼，底部任务栏显示目标要求；取消只丢弃本次草稿，不改已有目标。
- 选鱼前明确设置任意尺寸、MAX 最大、MIN 最小或 MAX＋MIN。该设置用于随后选择的鱼；已选鱼可单独修改，不能暗中批量覆盖旧条件。
- 例如选择 MAX 再点击虹鳟，保存的是“虹鳟 · MAX 最大”，钓到普通尺寸的虹鳟不完成目标。MAX＋MIN 分别显示完成状态，两项全部完成后才结束该鱼的要求。
- 目标清单和鱼获均显示鱼图。鱼获记录使用完整彩色图片，首次、彩色、最大、最小分别作为独立筛选，另有全部历史；图鉴及鱼获都支持小图和列表。
- 一次鱼获可以同时属于首次、彩色和最大等多个分类，但完整历史只保存一条。彩色稀有度与尺寸成就相互独立，不能互相代替。
- 已确认达成的条件自动移出待办；MAX＋MIN 完成 MAX 后只保留 MIN。全部达成后停止任务并清空待办，鱼获历史保留；不能自动切换为自由钓鱼继续运行。正式实现中完成条件的移除与鱼获保存应保证一致，避免重启后已完成目标重新出现。
- 设置页完整保留现有窗口适配、预期宽高、窗口检测与采用尺寸、QTE 四项时延、校准与采用建议、四项页面等待、逐帧诊断，以及保存／撤销／恢复默认。自动清包和保持唤醒仍放在钓鱼页的任务设置中。

## 与现有实现的边界

- 第四版交互原型用六个钓场的十九种攻略鱼图演示布局，包含彩色鱼；目标、运行状态和鱼获记录均为示例，不连接游戏、不保存个人配置。原型设置由源码的十项字段和默认配置生成；检测与校准保留入口但不执行。正式图鉴保留全部 84 种及现有筛选能力。
- 原型提供“模拟鱼获”验证普通尺寸不完成 MAX、MAX／MIN 分别清除、最终停止与历史保留。该演示入口不是正式产品功能，不能当作游戏识别或持久化已经实现。
- 目标和鱼获功能仍遵循 [目标方案](fish-targets.md) 中已确认的规则：跨岛、昼夜等待、全部目标完成；同一条鱼最大和最小是两项条件，不受星级代替。旧方案中的独立窗口安排由本草案提出替代，业务规则不变。
- 不因改版放宽失焦、锁屏或窗口变化后的停止保护。原型允许切换运行状态下的页面以讨论布局，不代表实机允许后台持续钓鱼。正式实现仍需按游戏窗口前台状态停止任务并同步展示原因。
- 原始鱼卡只取上半部鱼图，不把攻略作者尺寸或纪录当作用户鱼获；详情保留简体参考译名与来源说明。
- 后续功能按页面扩展，尚未实现的功能不在正式版放置可点击的空入口。

## 实现安排与结果

0.4.0 已将任务、图鉴、设置放入统一导航，并接入目标和鱼获页面。替换布局未重写 QTE 控制时序；离线与包验收结果见[0.4.0 交付记录](../development/cases/2026-09-14-release-0.4.0.md)。

主窗口负责导航与公共任务栏，各页面管理自身筛选、滚动和选中状态。任务控制器由应用层持有，切换页面不创建工作线程、不重置任务、不重新加载 OCR。UI 继续通过 app 服务访问数据；图片加载、筛选和日志展示不能进入 QTE 控制路径。

正式替换时验证：单一任务实例、开始／停止、失焦停止、关闭退出、配置保留、图鉴资源和繁简搜索、页面切换后状态保留、小窗口及 DPI 排版。通过后更新固定 dist 入口，不增加最终版本子目录。

## 0.4.1 实际桌面视觉对齐

按原型保留浅色页面、白色分区、青色选中态、图标导航、较大的页面标题与紧凑鱼卡。图鉴、目标和鱼获共用图片裁切与卡片呈现；后续 0.4.4 已按用户要求将列表和密集网格统一为右侧固定详情。目标选鱼复用图鉴组件，导航和返回仍属于目标流程。

样式由 theme 统一管理，导航图标按缩放绘制。鱼卡绘制留在 UI，图片经 app 服务读取，有界缓存不随反复缩放无限增加。自绘卡片保留 Tab／Enter／空格操作，刷新后恢复当前鱼卡焦点，拖出后松开不执行点击。圆角 ttk 底图使用不透明背景，避免 Windows Tk 对透明底图的重复重绘。

验证包含实际窗口截图、最小窗口与模拟 125%／150% 字体缩放；模拟缩放不是跨显示器 DPI 切换实测。交付证据见当前状态。

2026-09-15 鱼获时间补充：左侧按本地日期分组，组内按捕获时间倒序；日期筛选与成就分类叠加。小图显示尺寸与时分，完整时间放在固定详情区。列表保留相同分组与筛选，不混入另一日期的记录。
