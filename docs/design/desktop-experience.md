# 桌面应用整体交互方案

状态：此前五页面原型已被用户否定，仅保留作设计过程记录。
本文的五页面结构未采用，不是当前使用说明。后续方案见[脚本工具界面原型](desktop-script-prototype.md)；固定任务区、右侧日志/设置切换已随 v0.2.0 发布，当前操作见[使用指南](../user/usage.md)。

用户希望重新设计完整桌面应用。此前的配色、卡片和弹窗调整不作为本方案的整体结构。
本方案覆盖功能组织、页面导航、任务状态、设置编辑和维护取证；游戏识别与输入时序保持独立。

## 主窗口与导航

主窗口使用统一应用框架，左侧提供“钓鱼、运行记录、异常与截图、设备与设置、使用帮助”。
右侧显示所选页面；底部始终保留任务状态、停止原因与停止入口。
设置作为主窗口页面呈现，不再打开承载整份表单的独立窗口。
窗口首次在可用显示区域内居中，最小尺寸与缩放由正式实现阶段验证。
后续可记忆合法窗口位置，显示器断开后回退到当前可见区域。

## 页面职责

| 页面 | 主要内容 | 首要操作 |
| --- | --- | --- |
| 钓鱼 | 启动准备、当前任务状态、钓场与运行选项、近期事件 | 开始或停止任务 |
| 运行记录 | 按任务归组的运行过程、已确认鱼获、停止原因与日志等级 | 选择任务、查看记录 |
| 异常与截图 | 按观察类别选择证据，联动原图、元数据和处理状态 | 查看当时画面 |
| 设备与设置 | 客户区、输入时延、等待、诊断偏好 | 检测、采用建议、保存 |
| 使用帮助 | 首次使用、前台要求、参数含义和问题定位 | 跳转相关功能 |

导航按用户要完成的事情组织，不按游戏自动化步骤拆成页面。
开始页导航、岛屿选择等未来能力可以扩展任务配置，但在后端支持前不呈现为可执行操作。
当前钓场目录只有已有条目；不能因用户提及第六岛就编造名称或宣称已支持。

## 任务状态

| 状态 | 呈现 | 可执行操作 |
| --- | --- | --- |
| 待机 | 游戏是否可用、使用哪份设置、如何开始 | 设置、开始 |
| 启动检查中 | 当前检查步骤；开始禁用 | 停止 |
| 运行中 | 当前阶段；选项锁定 | 停止、查看已有记录 |
| 停止中 | 正在等待退出及释放输入 | 查看状态，不能重复启动 |
| 保护停止 | 触发原因、是否已释放输入、恢复操作 | 恢复游戏后手动开始 |
| 异常停止 | 可理解的原因与对应证据入口 | 查看记录、调整设置 |

原型可切换待机、运行中和保护停止状态；不连接游戏。
真实运行仍要求游戏前台，切到助手可能触发保护停止。页面不因浏览功能而放宽输入守卫，
也不以持续抓取游戏预览作为主界面的默认负载。

## 设置编辑

分为窗口与分辨率、时延与等待、记录与行为。时延中的页面等待和超时默认收起，
QTE 核心参数直接可见。每行呈现字段及单位、当前值、同位置建议和“采用”操作。

- 默认值明确标为参考，不冒充本机最优值。
- 检测成功后，宽高旁显示客户区实测像素；不自动覆盖正在编辑的表单。
- 校准只建议检测与反馈间隔，按住和松开等待仍需游戏实测。
- 编辑后显示未保存状态；切换页面保留草稿，保存才写入配置，撤销回到上次保存值。
- 任务运行时禁用修改；取消、关闭和保存失败均需在正式实现中覆盖。
- 保存与撤销固定在页面操作区，长内容滚动不遮挡动作。

原型的检测、校准、保存只改变演示状态。正式实现应复用 `DesktopServices` 的配置校验、
后台校准与取消机制，不建立另一套配置默认值或写入入口。

## 记录与证据

运行记录围绕一次任务组织，区分开始、QTE 反馈、整鱼结算、恢复与停止。
鱼获统计只使用已确认的结算事件；未确认、失败、主动中断分别呈现。

异常页使用列表与详情联动，而不是把文件系统目录直接作为界面层级。
详情保留原始类别、画面来源与时间。新增维护判断不能覆写原始证据或账本。
特殊外观即使未失败也可进入回看列表；外观标签不表示机制已实现。

原型使用三张已有回归样本展示图像详情，列表数据和任务记录用于设计演示。
正式桌面目前没有该完整记录浏览器；需新增只读记录索引服务，支持旧包缺失字段、坏包、
无截图与空目录等状态。打开文件夹与导出必须操作明确选择的文件范围。

## 视觉与性能

统一字体层级、间距、按钮主次、表单和反馈样式，提供浅深主题及紧凑密度的设计比较。
任务动作使用显著主按钮；日志、说明与维护信息降低视觉权重。
颜色与文字共同表达状态，不以颜色独自区分成功、警告或失败。

UI 只显示服务层提供的快照；状态和日志使用有界投递与合并刷新。
截图列表按需读取缩略图，不在 QTE 控制或输入线程中解压、编码、同步写盘或刷新界面。
界面改造不能引入新的按键队列、额外每帧截图或改变当前输入时序。

## 接入边界

原型用于确认整体交互，不是可以直接替代 EXE 的页面。
正式落地分为应用框架与任务页、内嵌设置、记录与证据浏览三个部分；公共样式、表单和状态条复用。
实现阶段再确定桌面组件方案及其依赖、包体和主题能力，不能仅凭原型推定必须更换技术栈。
完成后验证设置保存、取消、启停、保护停止、缩放与多显示器、记录兼容性，再构建完整便携包。
