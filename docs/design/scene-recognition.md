# 页面识别与启动接续

[项目架构](architecture.md) · [使用指南](../user/usage.md)

本文对应已打包的 0.3.0 本机版本。2026-09-11 已实测码头到亚特兰蒂斯的启动导航及钓鱼衔接；尚不覆盖游戏主页到码头的入口。

## 当前能力

| 状态 | 依据 | 启动行为 |
| --- | --- | --- |
| idle | 鱼钩抛竿按钮与方向字形 | 连续观察后允许抛竿；换点前、换点后均重新确认 |
| waiting | 水花按钮、SPACE，无方向键且无活动计时条 | 继续观察咬钩，不重抛；只在本次新帧确认等待且咬钩信号出现时按一次空格 |
| panel / result | “点击画面关闭”模板 | 复核后关闭；该分类只是可关闭面板，不代表确认鱼获 |
| panel / level_up | 关闭提示、LEVEL UP 标题、属性标签同时存在 | 关闭升级提示，再确认待机 |
| blocked_dialog | 返回码头、前往钓鱼地区或 150402 错误的模板 | 优先于背景待机识别；导航区分返回与换岛，换岛还需 OCR 核对目的地后确认一次，不使用结算关闭 |
| qte | 计时条、黄／蓝目标和实际亮光标同时存在 | 连续观察后接续当前鱼，跳过换点、抛竿和咬钩按键 |
| unrecognized | 未满足已知页面条件 | 限时只读观察；恢复已知页面后继续，否则记录并停止 |
| unavailable | 无图或截图尺寸不符 | 同上，不使用上一帧授权输入 |

QTE 画面不表示倒计时数字必然大于零；完整夜间回归图中含计时为 0 的残留 QTE。接管之后由既有控制与结算观察确认结果，不能把接管认定为捕获。
普通 QTE 运行期间仍允许暂时看不见光标／目标，由原机制策略处理；首次接管的门槛更严格。

以下能力仍是局部信号，不是独立页面识别：咬钩惊叹号、满包与位置受阻提示、地点名称、“更改”按钮、部分时间文字和 QTE 特殊外观。
等待咬钩已加入样本驱动的独立状态。码头与岛屿地图由启动前的 `game/navigation/voyage.py` 协调；主页、玩法入口、背包出售各级页面尚未纳入。不会把缺少 QTE 的现象解释为待机。

七张用户原图覆盖加载、码头、地图拖动、天空岛许可证购买前后和鱼种解锁，见[入口、选岛与许可证](../reference/voyage-navigation.md)。`voyage_reading.py` 负责图像与 OCR 读数；红色推荐等级、许可证和鱼种解锁分别输出。地图内选中与未选中圆标用于搜索，点击后重新确认岛屿名；只允许已确认的启航动作，购买入口停止并提示。

## 代码职责

- `scene.py`：纯识别，组合待机、面板和 QTE 外观读数；不截图、不按键、不写盘。
- `page.py`、`panels.py`、`dialogs.py`、`templates.py`：各类字形和页面依据。关闭提示模板从结算观察器迁入面板模块，保持原匹配门槛。
- `settlement.py`：截图、窗口保护、结果观察与统一页面读数；原结算入口保持兼容。
- `startup.py`：启动与等待咬钩接续的有界观察、页面分支，复用 `recovery.py` 的连续弹窗处理。
- `app/fishing_task.py`：协调入口，先确认待机再考虑换点；QTE 接续时跳过此分支。

桌面/session 启动先尝试航海导航，再选择钓场策略。码头/地图使用手动目标，自动模式采用当前确认选中的已支持钓场；直接在钓鱼场景启动时沿用原地点策略选择。未知或没有钓鱼策略的岛屿不会擅自启航。

## 时序与取证

启动观察复用 `recovery.page_wait_seconds`，默认 10 秒。待机连续确认至少约 200 ms，QTE 至少两次间隔约 50 ms 的观察；间隔之外还包含实际处理耗时。
弹窗关闭沿用现有的动作前复核、每类一次与关闭后等待预算。接管前后若 QTE 已结束，直接走原计时条消失与结算确认路径，不再等待 QTE 首次加载超时。

统一页面识别仅运行在启动、结算和轮次衔接，不放入逐帧 QTE 决策路径；按下时长、释放等待和检测间隔保持原值。
启动弹窗和异常包归 `startup/`，使用有界后台写入，不计入鱼获。停止或失焦后仅保留已有帧，不补截桌面。
接管鱼获标记 `resumed_qte=true`，此前的输入和反馈不纳入本次统计。

等待接续沿用原咬钩上限 15 秒；本次新帧未确认等待时，不使用缓存帧中的黄色像素触发输入。若提前进入 QTE 则直接接管；若恢复待机则复核后抛竿；超时或未知则保存并停止，不执行盲目移动/重抛。
普通等待超时同样先重新识别，再选择继续等鱼、接续 QTE 或确认待机后重抛。明确“当前位置无法抛竿”的一次移动恢复仍保留。
QTE 异常恢复发现连续等待画面时，通过 `round_recovery.next_state=waiting` 交回主循环，不追加轮间 4 秒等待，不把它当作允许再次抛竿。
`resumed_waiting=true` 标记经此路径接续的鱼获。识别只使用 UI 控件，不使用角色造型、朝向、船壳或昼夜海面。

## 验证与后续

2026-09-11 用户提供等待图及抛竿前正、背面图，确认水花按钮属于等待；此前无方向键待机样本重新分类为 waiting，保留文件名和历史说明以便追溯。
等待图（933×527）、背面待机（948×530）、两张旧水花图通过状态对照。正面图（928×511）边缘截取范围不同，当前识别返回未知，未降低匹配门槛或新增角色模板强行放行；它作为正面 UI 参考保留。
水花/SPACE 的局部搜索范围扩展到参考宽 945 下的 ±16 px，仍要求 0.88 分数；这不会把截图尺寸差当成状态依据。
397 项完整离线测试通过；覆盖新样本、启动等鱼、咬钩只按一次、QTE 不重复拉竿、等待超时不重抛、异常后的等待转交，以及既有结算/机制/窗口保护回归。
上述离线检查之后，已实测码头导航、完整客户区正面待机、抛竿受阻恢复及三轮捕获，见[9 月 11 日实测](../development/cases/2026-09-11-voyage-navigation.md)。已纳入 [0.3.0 本机包](../development/cases/2026-09-11-release-0.3.0.md)；不同昼夜/船型的等待帧、从等待/QTE 中途启动和完整特殊机制组合仍需继续覆盖。

150402 专用退出重进已接入源码但未打包，详见[航海恢复](../reference/voyage-navigation.md#150402-错误的退出重进例外源码新增未实测打包)。普通导航仍不自动返回码头。
